# Branching Policy

## Always Create a Branch
- **NEVER** commit directly to the `main` or `master` branch.
- **ALWAYS** create a new branch for any code change, no matter how small.
- Branch names should be descriptive, following the pattern: `type/description` (e.g., `feat/add-login`, `fix/typo-in-readme`).

## Pull Requests
- All changes must go through a Pull Request (PR).
- PRs must pass all automated checks before merging.
